# ApocaLab v1 重建实施计划（审核稿）

> 状态：**仅供方案审批；尚未实施，不代表任何性能或数据验收通过。**  
> 项目：`apocalab.com` · 面向美国用户 · 公开页面、标题、结构化数据与编辑内容使用英文  
> 更新：2026-11-10  
> 范围：**仅阶段一**。不编写产品代码，不提前启动阶段二。

## 0. 决策摘要

采用指定技术栈：**Astro + TypeScript SSG、MapLibre GL JS、Canvas 2D、构建期 Python、静态 JSON/GeoJSON、URL 查询参数和 GitHub→静态 CDN 部署**。不使用账号、后端、付费 API、卫星影像或 3D。将原先以免责声明为核心的页面叙事彻底删除：主画面优先地图、图例、对比表格和有出处的事实数据，方法论单独集中在 `/methodology/`。

工程能够实现：20 个城市的静态内容、地图选择/城市搜索、状态分享、底图切换与容错、基于既有公开资料的历史对照数值表、人口栅格的数据准备、SEO 静态页面、构建期 PNG 社交卡片，以及独立的事实核查与方法学页面。

**需要调整的产品边界**：不规划以任意坐标和核装置当量为输入、推算具体地点的破坏半径、24 小时放射性落尘轨迹及受影响人数的可执行计算模型；也不提供这些模型的可复现武器效应公式、系数或实现。该组合可以用于现实地点的攻击后果评估。替代路线是提供**有明确来源的历史实测数据、研究中发表的汇总比较、非预测性的示意层，以及不与攻击结果挂钩的公共人口统计背景**。这不等同于把数字从产品中删除；而是严格区分“已有证据支持的数字”和“无验证基础的地点预测”。因此，原需求中若干交互验收项需要产品负责人重新批准为“参考数据比较”口径，不能虚报为已达成。

## 1. 技术架构与目录职责

| 层 | 选型 | 实施约束 |
|---|---|---|
| HTML / SEO | Astro SSG | 每个路由预渲染，初始 HTML 含正文、静态数据表、内链；JS 只增强地图交互 |
| 交互 | 小型 TypeScript islands | 不引入整站客户端 SPA；浏览器 History API 写入/读取 URL 状态 |
| 地图 | MapLibre GL JS | Map-style 配置是独立单一入口，适配 style URL 和本地 style JSON |
| 示例范围与辅助动画 | 独立 Canvas 2D | 有测量依据的图形和氛围效果分不同图层；氛围图形不带数值刻度 |
| 地名 | GeoNames 离线构建索引 | 前端只加载压缩后的所需城市/地点索引，无 GeoNames 在线 API |
| 人口背景 | WorldPop Global2 1 km 栅格 | Python/GDAL 或 rasterio 构建期读取；原始巨型 GeoTIFF 不下发浏览器 |
| 图表 | 构建期生成 SVG/PNG 与 HTML 表格 | 图表图像是辅助，表格中的数值与来源在关闭 JS 后可读 |
| 资源 | 同域 JSON、GeoJSON、PNG、CSS、JS | 业务数据不调用第三方实时接口；**地图瓦片本身仍需网络加载** |
| 部署 | GitHub → Vercel 或 Cloudflare Pages | 完全静态，部署前构建，CDN 分发 |

建议的代码模块边界（**这是设计分层，不是已创建的目录**）：`src/config/map-sources`、`src/data/cities`、`src/data/references`、`src/lib/url-state`、`src/lib/map-adapter`、`src/lib/presentation`、`src/components`、`src/pages`、`scripts/data`、`scripts/og`、`tests`。SEO 文案由单独的 route metadata 管理，禁止从旧 demo 复制页面段落。

可迁移且需先审查的原 demo 模块限定为：(1) 选点、投影和 URL 状态；(2) 缩放映射与播放时坐标固定；(3) `idle → selected → playing → finished` 状态机及最后画面保留；(4) 20 城市坐标。尚未取得源代码审阅权，不承诺这四项已经可直接复用。其他页面骨架、免责声明布局、文案及防御性叙事不迁入。

## 2. 底图：唯一配置入口、两套独立来源、三层回退

### 2.1 主源

- 提供商：**OpenFreeMap 公共实例**；主风格优先 **Fiord**，备选 **Dark**，均为深色低饱和矢量。
- 官方 style URL：`https://tiles.openfreemap.org/styles/fiord`；同提供商的替代样式 `https://tiles.openfreemap.org/styles/dark`。
- 官网公开声明：无需注册、API Key、Cookie；地图浏览量与请求量不设公开计费配额；**允许商业使用**。这不等于承诺 SLA 或永不调整公共服务政策。
- 署名始终可见：`OpenFreeMap © OpenMapTiles Data from OpenStreetMap`，相应实体链接和底层数据许可证按实际样式资源保留；在小屏也不能隐藏。

### 2.2 独立备用源

- **VersaTiles 公共矢量图瓦片**，使用本地受版本控制的暗色 MapLibre style JSON 指向该源。官方可核实的公开样式示例：`https://tiles.versatiles.org/assets/styles/colorful/style.json`；正式接入时使用其可用瓦片和自有深色 style，而非直接上线彩色演示图。
- VersaTiles 公开服务无需 API Key、无需使用量付费，按 IP 限速、无 SLA，官方将其定位为公共演示服务并提醒版本变更。**所以它是尽力而为的备援，不是有可用性保证的生产托底**；后续高流量应评估自行托管或得到明确服务承诺。
- 备用源署名使用其 TileJSON / style 所要求的**真实来源署名**，不错误地继续显示主源标签。若自有 style，必须把必要署名显式放入页面。

### 2.3 回退状态机

`OPENFREEMAP_FIORD → OPENFREEMAP_DARK (仅换风格) → VERSATILES_DARK (独立数据服务) → LOCAL_DARK_CANVAS`。

一次配置定义源标识、style URL/对象、资源许可信息、超时和失败条件；页面组件只接入 `mapAdapter`，不得硬编码域名。监测 `error`、`load`、`idle`、资源失败和首帧超时；请求失败后限制重试次数，禁止无休止 Loading。全失败时从一开始就存在的纯色深底保留，Canvas 2D 仍能绘制**明确标注为示意的图形**，右下角仅一行 `Map tiles unavailable`。MapLibre/WebGL 初始化失败也应触发 Canvas 独立兜底。此时不可将没有地理底图定位支持的示意圈误表述为精确地理范围。

**上线前必须完成实测**：两个源的 style、tile、glyph、sprite、CORS 和 HTTPS 都加载成功；断网、DNS 故障、403/404/429、WebGL 不可用的兜底行为；移动端署名可见。不能仅凭官方文档把第二源标记为“已经实测可用”。

## 3. 科学内容、公式出处、误差与可发布数字

### 3.1 科学数据分类

| 层级 | 可发布内容 | 数据如何产生 | 页面上如何命名 |
|---|---|---|---|
| A：可追溯观测 | 已公开历史事件中有明确出处的量测与观测范围；独立的历史统计 | 引用原始论文、报告、档案，保留年份、单位、来源版本及测量定义 | `Recorded` / `Observed` |
| B：研究发表的汇总值 | 经同行评议研究中的**总体**气候与环境影响统计 | 引用具体论文表格/图件和研究设定，不把研究条件硬套到某城市 | `Published estimate` |
| C：视觉引导 | 动画圈、烟雾、扩散时间轴、风向图形 | Canvas/GeoJSON 艺术化生成，不输出地点级武器效应结果 | `Illustration — not a forecast`（只在图例/说明处） |
| D：人口地理资料 | 城市的公开人口估计、来源年份和行政区域定义 | WorldPop 栅格的区域统计（与爆炸影响范围不做空间叠算） | `Population context` |

**不实现的计算**：按当量及爆点输出实地火球/5 psi/1 psi/热效应半径；地爆、空爆的可复现破坏模型；按风向与小时预测真实地点的沉降足迹；将人口格网与上述攻击效应区叠算为“受影响人数”。也不指定这些武器效应公式的出处章节、系数或误差数值。这与现有 `computeImpact(...)` 验收契约存在**明确未解决差异**，不得给这些字段填猜测值。

### 3.2 可在工程中明确记录的非武器公式

- **视图缩放联动**（来自现有交互规格）：屏幕尺度系数 `s = 2^(currentZoom − referenceZoom)`。仅用于在相同投影条件下保持装饰/标注图形的视觉尺度一致；不是破坏半径计算式。
- **栅格人口区域统计**：按数据生产者提供的每个网格单元 `population_count` 值，在统一行政区域定义下聚合；缺值（NoData）不当成零，按覆盖比例与质量标志报告。不对爆点半径圈进行人口求和。
- **数据有效性**：数值卡片必须附带 `source_id`、`year`、`unit`、`geography`、`measurement_definition`、`validation_status`；构建时拒绝缺来源的数字。图表显示范围不能超出原研究可支持的范围。

### 3.3 落尘模型边界与误差量级

原需求的“单层风、无降水、无地形、24 小时”若用于真实地点预测，会忽略风向随高度和时间变化、降水清除、粒径差异、沉积与地形，**无法仅凭该简化设定推出可信的地点级误差量级**。不能擅自声称 ±10%、±30% 等精度；本期只提供**非预测性风向示意和基于既有公开案例的定性时间序列**。其误差在“地点预测”意义上不可量化且不予输出。方法学将此列为研究边界，而不是在首页大篇幅解释。

### 3.4 额外的物理概念风险

“空爆就一定不接地”不是普遍成立的判断，是否接地还与爆发高度及情景有关。页面避免把 `burstType` 直接等同于一个不加条件的物理结论。更不以视觉云团大小表示真实半径；示意层与有来源的数据层需要不同图例、线型和层级。

### 3.5 数字审核门槛

每条数值必须能追溯到研究或数据集的某一项、日期、单位、情景定义与适用条件。不存在支持证据时**不生成该单元格或城市页**，不以 0、`N/A` 的假数、默认平均值代替，更不能将人口背景数字叫作人员伤亡。

## 4. 人口与地名数据：来源、许可和预处理

### WorldPop

选 **WorldPop Global2 R2025A v1，2025 年，全球 1 km 人口格网**（正式下载以 WorldPop 元数据指向的版本及发布情况为准；保持版本锁定），许可证 **CC BY 4.0**。明确区分“每格估计居住人口”与“实时在场人数”；它不提供昼夜移动、建筑内人数、避难状态或任何伤亡率。原始 GeoTIFF 大小和区域覆盖将先在小样本上核实。

构建期数据流水线：
1. 锁定数据 DOI / 下载地址 / 校验和 / 年份 / 许可证与 citation；原始文件只存构建数据存储，不提交到网站包。
2. 用 Python 的 rasterio / GDAL 验证 CRS、NoData、像素人口计数与海陆边界；仅在必要时重投影或进行掩膜计算，避免将密度值与人口计数混淆。
3. 为 20 城市分别确定**明确、可引用的统计边界**（行政市界或都市区，固定一种口径），计算区域人口背景并保存质量标志和原始来源。
4. 导出城市级小 JSON 以及与视图有关的少量、可压缩地图资源。构建报告核对 20 个城市的名称、边界、地理坐标、数据缺口。
5. 站点运行时仅使用已构建的同域静态资源；不会调用 WorldPop API。未经数据验证，不将地图上任意点击点转换为精确人口影响预测。

**不可同时许诺的三项**：全球任意坐标、1 km 空间精度、零网络业务数据且首次点击 300 ms 内得到任意范围人口结果。有限客户端包或 CDN 按需瓦片能做到其中部分目标，但需要资源体积、首包时间与缓存预算的产品取舍。当前阶段先做固定城市静态值，其他点使用基本地图交互而非未核实的人口数。

### GeoNames

下载官方每日离线导出，基于城市别名、ASCII 名、国家/地区/坐标去重；保留 20 城市的官方或公认英语名称及国家消歧。GeoNames 数据为 **CC BY**，支持商业使用；只使用下载数据，不使用其受配额限制的在线搜索接口。城市介绍不能由地名数据库“自动编造”，需单独事实核查、英文编辑。

## 6. SEO 内容契约（只做阶段一）

每条已批准页面独立配置 `title`、`h1`、`description`、`canonical`、`ogTitle`、`ogImage`、`internalLinks`、`schema`。关键字映射保留：

| 路由 | 主关键词 | 处理 |
|---|---|---|
| `/` | `nuke simulator` | Title 与 H1 都出现词组且不重复为同一句；正文避免虚构计算承诺 |
| `/blast-radius/` | `nuclear bomb blast radius` | 解释已公开测量及研究中的半径定义，首屏有可读表格 |
| `/fallout-map/` | `fallout map` | 描述示意风向和历史公开观测，不宣传实时辐射预测 |
| `/nuclear-bomb-map/` | `nuclear bomb map` | 独立导航入口、城市与研究资料索引 |
| 20 城市页 | `what would happen if a nuke hit <city>` | 关键词需与实际受支持内容匹配，不能用人口背景伪装成地点预测 |
| `/nuclear-winter/` | `nuclear winter` | ≥3000 英文词、可核验图表与来源 |

- Title / H1 各自原创且包含主词；description 逐页编写；`og:title === document.title` 在构建期断言。
- `canonical` 必须是 `https://apocalab.com/...`，不带预览域名，也不将任意 URL 参数单独当成可收录页面。
- `sitemap.xml` 来自 Astro SSG 构建的全部准入路由，`robots.txt` 指向正式 sitemap；阶段二批准后才自动新增第二阶段路由。
- 首页/可见 FAQ 区加准确匹配页面可见问答的 `FAQPage`；城市页加 `BreadcrumbList`。注意：Google 对普通商业网站的 FAQ 富摘要展示已经受限，**写上 Schema 不保证搜索结果出现 FAQ 富摘要**。
- 关闭 JavaScript 仍能看见主标题、核心文章、表格、地名信息、至少三条有效站内链接；城市页必须链接首页与 `/blast-radius/`。
- OG 图片统一构建期输出 **1200×630 PNG**，不输出 SVG 作为 `og:image`。每个**预先生成的有限案例/城市**有独立 PNG，包含案例标题、明确来源的数字和可归属的示意图。所有任意坐标的无限组合不可能由纯 SSG 在请求时生成独立图片；此类共享 URL 回落到所属页面的静态 OG 卡片，或者以后另行批准动态图片服务。
- 禁止出现历史 demo 的营销/占位语句及整段旧文案。上线前通过字符串扫描、链接扫描与 HTML 断言检查。
- 不承诺通过 SEO 技术本身取得搜索排名；先保证可索引、准确、速度与内链。

## 7. 状态、动画、响应式与验收测试

### URL 和状态

- 约定 `?lat=&lng=&kt=&z=` 是兼容旧分享链接的解析格式。`kt` 可以作为**选择与显示的历史情境标记**，不得成为前端计算地点级武器后果的输入。
- 额外使用 `mode`、`wind`、`t` 表示说明视图、示意方向和时间帧；参数值有限集合校验、经纬度边界检查、纠错和 URL 去噪。
- 浏览器 Back/Forward 能还原状态；不刷新可切选项，所有浏览器交互都有可触摸的替代按钮。
- 动画状态机 `idle → selected → playing → finished`，播放时锚点不可变，结束保留静帧；重新选点才复位。尊重 `prefers-reduced-motion`。

### 视觉与数据分离

“有来源的数字”放在 HTML 结果表或数据卡；动画独立透明层，使用不同线型/图例，任何装饰图形不得借用数据量纲。没有被验证为地点级物理范围的圆形不得描成“真实计算范围”。页面不以大段免责声明占据首屏；只在图例、方法页以及需要解释数据类型的位置作必要说明。

### 性能预算和测量

| 指标 | 目标 | 如何验收及限制 |
|---|---|---|
| 首屏 2 s | 静态主体、地图区域、默认数据均可见 | 以约定网络与手机设备做 WebPageTest / Lighthouse 实测；瓦片完整加载不保证 2 s |
| 交互 300 ms | 输入到**本地展示层**状态更新 ≤300 ms | 预加载后取 P95；排除首次全球数据下载；不能把异步未知数假报成功 |
| 风向示意切换 500 ms | 本地 Canvas 时间轴重绘 ≤500 ms | 普通中端手机、4–8 档切换 P95 |
| 禁 JS | 核心正文/表格/链接存在 | Playwright 禁 JS + 直接读取编译后的 HTML |
| 断网/底图失败 | 有深底、有内容、无无限 spinner | 阻断两个瓦片域名、WebGL 出错和模拟慢网分别测试 |
| 图片分享 | 各预渲染页面输出 PNG | 构建校验 MIME、像素尺寸、`og:title` 完全一致、HTTP 200 |
| A11y | 移动端可用 | 360/390/430px 视口、触摸面积、键盘、对比度、动效减弱 |

## 8. 明确风险 / 待批准决策

| 编号 | 风险或冲突 | 严重度 | 需要的处理 |
|---|---|---|---|
| R1 | 用户指定的地点级核爆半径、落尘轨迹、人口伤亡效应引擎涉及可执行攻击后果评估 | **阻断** | 将 v1 数值范围批准为历史观测、研究汇总和公共人口背景；不实现地点级预测引擎 |
| R2 | 纯 SSG 不能实时产生无限个地点/当量组合的专属 OG PNG | 高 | 接受有限预生成卡片 + 动态分享回落到页面静态卡片 |
| R3 | 全球 1 km 人口数据与任意点击即时零请求有体积和性能冲突 | 高 | 阶段一只预生成 20 城市人口背景；之后依据真实测量再决定资源分片方案 |
| R4 | 公共免费地图源未承诺 SLA；备源亦限速 | 中高 | 故障注入与纯色兜底必做；流量增长时评估自托管 |
| R5 | “空爆就不接地”属于过度简化；沉降图形不可视为现实预测 | 高 | 内容审校与方法页明确概念边界 |
| R6 | 人口格网不是实时在场人口；城市边界口径不一致导致数据不可比 | 高 | 每页给数据年、城市边界定义和质量元数据 |
| R7 | 旧 demo 只提供部署 URL，尚未审查源代码授权、依赖与可迁移性 | 中 | 取得 GitHub 仓库或压缩包后，仅迁移被批准的四个模块 |
| R8 | 首屏 2 s 与公共地图瓦片首次加载受网络影响 | 中高 | HTML/静态预览先渲染，底图异步增强，真实设备测试并报告 P75/P95 |
| R9 | 网站计划未来有订阅，法律页面与隐私披露需要依据实际部署和第三方网络请求 | 中 | 发布前核实 Cookie、分析、地图请求与法律适用；需法务复核 |
| R10 | 含“受影响人口”的不明指标不可与城市总人口混用 | 高 | 严格改为 `Population context`，明确数字分母、区域与年份 |

建议只有在 R1、R2、R3 的范围变化获批准之后，才开始编码。若产品要求保持原样，则它们不能被标记为“技术上已满足”。

## 9. 阶段实施与回报模板

阶段实施顺序固定：**可信数据与计算边界 → 首页 → 半径参考页 → 底图及视觉 → 落尘示意页 → 核地图页 → 20 城市页 → 冬季/方法/法务内容页 → 全站 SEO、QA 和部署**。没有批准，不进行阶段二武器页。

每阶段交付统一格式：

1. **对应验收 / 实际变更**：完成的路由、提交、静态输出与截图。
2. **验收对照**：逐项 `PASS / FAIL / BLOCKED`，失败写可复现原因和性能数据，不用“基本完成”。
3. **来源与可信度**：所用公开资料的版本、许可、引用、数据含义、误差或不可量化边界。
4. **问题与依赖**：真实缺陷、需要产品负责人提供的 repo、合法数据访问、路线决策、账号（如有）。
5. **下一阶段**：只推荐下一优先级事项，说明是否存在阻塞。
