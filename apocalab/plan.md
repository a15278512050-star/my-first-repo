## 0. 决策摘要

采用指定技术栈：**Astro + TypeScript SSG、MapLibre GL JS、Canvas 2D、构建期 Python、静态 JSON/GeoJSON、URL 查询参数和 GitHub→静态 CDN 部署**。不使用账号、后端、付费 API、卫星影像或 3D。将原先以免责声明为核心的页面叙事彻底删除：主画面优先地图、图例、对比表格和有出处的事实数据，方法论单独集中在 `/methodology/`。

工程能够实现：20 个城市的静态内容、地图选择/城市搜索、状态分享、底图切换与容错、基于既有公开资料的历史对照数值表、人口栅格的数据准备、SEO 静态页面、构建期 PNG 社交卡片，以及独立的事实核查与方法学页面。

**需要调整的产品边界**：不规划以任意坐标和核装置当量为输入、推算具体地点的破坏半径、24 小时放射性落尘轨迹及受影响人数的可执行计算模型；也不提供这些模型的可复现武器效应公式、系数或实现。该组合可以用于现实地点的攻击后果评估。替代路线是提供**有明确来源的历史实测数据、研究中发表的汇总比较、非预测性的示意层，以及不与攻击结果挂钩的公共人口统计背景**。这不等同于把数字从产品中删除；而是严格区分“已有证据支持的数字”和“无验证基础的地点预测”。因此，原需求中若干交互验收项需要产品负责人重新批准为“参考数据比较”口径，不能虚报为已达成。

## 1. 技术架构与目录职责

| 层 | 选型 | 实施约束 |
|---|---|---|
| HTML / SEO | Astro SSG | 每个路由预渲染，初始 HTML 含正文、静态数据表、内链；JS 只增强地图交互 |
| 交互 | 小型 TypeScript islands | 不引入整站客户端 SPA；浏览器 History API 写入/读取 URL 状态 |
| 地图 | MapLibre GL JS | Map-style 配置是独立单一入口，适配 style URL 和本地 style JSON |
| 示例范围与辅助动画 | 独立 Canvas 2D | 有测量依据的图形和氛围效果分不同图层；氛围图形不带数值刻度 |
| 地名 | GeoNames 离线构建索引 | 前端只加载压缩后的所需城市/地点索引，无 GeoNames 在线 API |
| 人口背景 | WorldPop Global2 1 km 栅格 | Python/GDAL 或 rasterio 构建期读取；原始巨型 GeoTIFF 不下发浏览器 |
| 图表 | 构建期生成 SVG/PNG 与 HTML 表格 | 图表图像是辅助，表格中的数值与来源在关闭 JS 后可读 |
| 资源 | 同域 JSON、GeoJSON、PNG、CSS、JS | 业务数据不调用第三方实时接口；**地图瓦片本身仍需网络加载** |
| 部署 | GitHub → Vercel 或 Cloudflare Pages | 完全静态，部署前构建，CDN 分发 |

建议的代码模块边界（**这是设计分层，不是已创建的目录**）：`src/config/map-sources`、`src/data/cities`、`src/data/references`、`src/lib/url-state`、`src/lib/map-adapter`、`src/lib/presentation`、`src/components`、`src/pages`、`scripts/data`、`scripts/og`、`tests`。SEO 文案由单独的 route metadata 管理，禁止从旧 demo 复制页面段落。

可迁移且需先审查的原 demo 模块限定为：(1) 选点、投影和 URL 状态；(2) 缩放映射与播放时坐标固定；(3) `idle → selected → playing → finished` 状态机及最后画面保留；(4) 20 城市坐标。尚未取得源代码审阅权，不承诺这四项已经可直接复用。其他页面骨架、免责声明布局、文案及防御性叙事不迁入。

## 2. 底图：唯一配置入口、两套独立来源、三层回退

### 2.1 主源

- **主源**：OpenFreeMap 公共实例，Fiord 深色矢量样式，固定 `styleUrl = https://tiles.openfreemap.org/styles/fiord`；同提供商候选风格：`https://tiles.openfreemap.org/styles/dark`（不算独立备用数据源）。详见 https://openfreemap.org/quick_start/ 。
- **配置文件唯一入口**：`src/config/map-sources.ts`（拟建，尚未写代码）。由该文件维护三个 source descriptor；页面不能包含任何地图厂商 URL。描述符字段：`id`、`kind: style-url | local-style | solid`、`styleUrl?`、`attributionText`、`attributionLinks`、`timeoutMs`、`priority`。所有页面只请求 `src/lib/map-adapter.ts` 暴露的 `initialize(viewport)`、`switchSource(id)`、`getStatus()`，监听统一 `ready | degraded | unavailable` 状态。
- **更换底图的变更量**：同一 provider 下换 style URL，原则上仅修改 `src/config/map-sources.ts` **1 个文件、1 行 URL**；新增或更换 provider，原则上仍只修改同文件 **1 个 descriptor（通常 3–8 行字段）**，且同步核验署名与许可；不修改任何页面文件。此为接口设计验收目标，不是已实现的事实。
- **授权与配额**：OpenFreeMap 官网声明公共实例免费、不限地图浏览量/请求量、无注册/API Key/Cookie、允许商业使用；但**无 SLA**，不保证永不变更条款。资料：https://openfreemap.org/ 。地图数据和样式仍需履行实际许可证要求。
- **署名确切文案**：`OpenFreeMap © OpenMapTiles Data from OpenStreetMap`；在地图视口**右下角**固定可见、可点击各来源链接，距边缘约 8 px，适配手机安全区；不能被面板遮住。MapLibre 的 attribution 控件与独立 DOM 署名择一实现，避免重复。即使底图失败也保留最后已知正确的数据源署名；在源发生切换时同步改变署名。

### 2.2 独立备用源

- **独立服务**：VersaTiles 公共瓦片服务（与 OpenFreeMap 不共用图块域名）。备用风格采用 `gray-dark` 视觉方案，候选样式端点 `https://tiles.versatiles.org/assets/styles/gray-dark/style.json`。官方确认 `gray-dark` 是预置深色主题，但**该精确端点尚未完成 HTTP/CORS/瓦片端到端验收**，不可写作“已可用”。如果候选路径失效，则把版本锁定的 `gray-dark` style JSON 构建期内置为 `public/maps/versatiles-gray-dark.json`，其中 TileJSON、glyph、sprite、tile URL 均需确认与 MapLibre 兼容。参见：https://versatiles.org/versatiles-style/ 和 https://docs.versatiles.org/guides/use_tiles_versatiles_org 。
- **实际接入门槛**：构建/冒烟测试分别检查 style HTTP 200、JSON 结构、字体/glyph、sprite、矢量 tiles、CORS、深色背景、移动端首帧以及地图署名；未通过不得将 `secondary` 设为已验证。VersaTiles 自称公共演示服务，无 SLA、会发生样式和资源更新、按 IP 限速、超限返回 HTTP 429，客户端遵守 `Retry-After` 与响应缓存规则；不能把它当成有商用可用性承诺的免费 SLA。
- **备用源署名**：依 VersaTiles 所发布 style/TileJSON 中**真实**的 `attribution` 显示（含相关 OSM 数据归属），不可在它实际供图时仍强行标记成 OpenFreeMap。独立署名控件保持地图右下角同一位置；若构建本地 style，不得丢失来源字段。

### 2.3 回退状态机

`OPENFREEMAP_FIORD → OPENFREEMAP_DARK（同厂商风格自救） → VERSATILES_GRAY_DARK（独立瓦片来源） → LOCAL_DARK_CANVAS（离线纯色兜底）`。

- 状态机只存在于 adapter；设置有界首次加载超时、失败后有限次重试，区分 404/403/429/断网、瓦片错误和 WebGL 初始化异常。地图请求出现大量 tile 错误、未能进入 `ready` 或遇到 `429` 时转入下一候选，不能无限 `Loading map…`。
- **最终降级的确切画面**：地图区域仍占位，底色 `#0B0E13`，保留城市标签、选择点与**明确标为示意的 2D 视觉圆形**；操作面板和已有静态数据仍可读；地图**右下角**只有一行状态 `Map tiles unavailable`，不遮住署名或导航。由于 WebGL/瓦片均不可用时已失去地理定位与投影条件，Canvas 图形不得再宣称为精确地图测量范围。
- 对移动端视口需同时验证 `360/390/430 px` 宽度：定位按钮不被遮挡、署名可见、数据可滚动、图层不阻挡交互。
- **最终验收**：主源、备用源的 style→tile→glyph→sprite 真正加载成功；人为阻断主源时能到备源、同时阻断两源时能到纯色；禁 JS 时仍有静态地图容器和文字内容。上述验证目前尚未执行。

## 3. 科学内容、文献转录、数据溯源与发布边界

> 变更性质：依据产品负责人 2026-11-11 的“第 3 节替换版”更新。本次只更改第 3 节，**不改动其他章节或文档结构**。本节关于数值来源、核验方式和允许的产品行为属于最新要求；与第 0、5、6、7、8、9 节仍有不一致之处，须在下一轮统一修订，不能仅凭本次更新宣布整体 plan 获批开工。

### 3.1 数值来源定位：只接受可核对的原始文献转录

- **效应参考资料的唯一指定原始来源**：Samuel Glasstone、Philip J. Dolan（编），*The Effects of Nuclear Weapons*，第三版，1977 年，美国联邦政府出版物。原版政府出版物属于公有领域；第三方电子版的扫描与排版质量仍需单独检查。
- 已从公开目录与政府出版记录确认书名、编者、版本、年份和政府出版身份。**尚未逐项核对具体核效应数值及其图/表/纸本页码**；这里不制造貌似已核验的页码、曲线读数或来源编号。
- 此处的“唯一来源”仅约束**核效应参考值**，不替代第 4 节的 WorldPop 行政区域人口背景数据，也不替代核冬季页面所需的气候研究文献。
- 不编写、不运行、也不从本手册推导或拟合任何核武器效应公式；不对缺失当量插值或外推；不使用二手网页拟合结果冒充手册原文。
- 区分 **“书中原文确实列出的数据”**、**“编录人员从图中人工读出的近似值”**、**“无法核对的候选值”**。只有经人工对照并记录准确纸本定位的内容才可进入已核验参考档案；从图读值必须标注读取不确定性，不能标为精确表值。

### 3.2 References 数据契约与入库质量门禁

按要求保留以下数据字段作为**来源记录的模式定义**，但**不在此文档提供用于任意真实地点效应预测的数值表**：

| 字段 | 类型或约束 | 录入要求 |
|---|---|---|
| `effect_type` | 枚举：`fireball` / `psi5` / `psi1` / `thermal` | 四种类型保持独立；热辐射必须解释所采用的判据 |
| `yield_kt` | 正数或留空 | 仅转录原文明确给定的条件；不得程序拟合其他档位 |
| `burst_type` | `air` / `ground` / `not_specified` | 原文不明确时不可擅自推断为某一种 |
| `value_km` | 数值或空 | 只允许来自明确来源的人工核对值；**本版计划不填入武器效应数值** |
| `source_chapter` | 原文标识 | 逐条引用准确章节 |
| `source_figure_or_table` | 图/表标识 | 原文无对应图/表时必须拒绝该条入库，而非编造 |
| `source_page` | 1977 纸本页码 | 与 PDF 阅读器页序分开；没有核实就保持空，不能发布 |
| `notes` | 文本 | 记录定义、单位、情景、读取方式、限制和不确定性 |

配套的内部质量元数据建议包括 `edition`、`source_document_id`、`transcription_method`（直接表值/人工读图）、`reviewer`、`review_date`、`verification_status`。原八个业务字段不变；质量元数据不承担补造数据的作用。

**入库门禁**：三个定位字段（章 + 图/表 + 纸本页码）必须齐全且人工核验；记录原始单位与转换理由；图线读数不可当作无误差实测。无法访问原始图页、页码不清或镜像扫描质量不足时，标记 `NEEDS_SOURCE_PAGE`，请求产品负责人提供对应纸本页截图或 PDF 页，而不是猜测。

**可实现的验证**：对数据契约、字段枚举、引用格式、来源完整性进行静态校验；随机选取 5 条已发布的**非目标化参考记录**，由人逐项对照纸本原文，任何不一致即不能通过来源验收。

**发布边界**：即使每个半径数字都原样来自公开手册，将“当量 + 任意真实经纬度”映射为真实比例的火球、冲击波或热效应覆盖圈，仍会形成具体地点的武器后果评估工具。**因此，本阶段不实现这一地理化覆盖功能或其可执行取值/绘制链条**。可提供来源目录、原始文献的背景说明、历史观测案例的出处追踪、非地理定位的说明性图形和独立人口背景资料。不能把该限制描述成“技术上已验收通过”。

### 3.3 落尘模型边界与误差量级

**v1 落尘页仅实现非预测性风向说明与已有案例时间轴**，不把视觉扇区标成会经过现实街区的核落尘足迹。下表逐一冻结产品实现口径，避免出现“默认参数暗中算出数字”的伪模型：

| 项目 | 当前明确决定 | 实现/验收边界 |
|---|---|---|
| 风场层数 | **不采用单层或分层风场预测** | 风向为 UI 选择的抽象方向，不读取实时气象、不解平流方程 |
| 风的高度层 | **未选定物理高度** | 不宣称某个高度的风能够代表烟羽或沉降 |
| 风速范围 | **不设置预测风速区间** | 页面不能出现基于某个风速推导的真实沉降距离 |
| 粒子沉降速度 | **不设颗粒半径、速度或沉积系数** | 不进行落尘浓度或剂量计算 |
| 计算时间步长 | **无物理积分时间步长** | 动画刷新由 UI 帧率控制，不是沉降求解步长 |
| 24 h 分段 | 只保留 **0 h / 6 h / 12 h / 24 h** 四个可分享的说明视图 | 时间标签表示教学阅读顺序，不是每个时间点的实时预测 |
| 图形生成 | 可采用固定屏幕尺寸的、无距离刻度的**抽象半透明扇形**，不采用经纬度关联的椭圆沉降模型 | 扇形方向可以随 UI 旋转，但不生成 GeoJSON 地面沉降范围，也不叠加人口格网 |

**何时会明显出错（两个具体场景）**：① 冷暖锋过境时不同高度及不同时刻的风向发生快速变化，单一地面风向箭头无法代表运输路径；② 雷暴或强降水时出现显著湿沉降，均匀的示意扇形会完全错置局部沉积区域。复杂地形也会改变近地风场。

**误差量级**：对现实地点的沉降范围、剂量或受影响人口，本期**没有可以验证的百分比误差**，应写为 `Not estimated / Not validated`，而不是编造 ±10% 等数值。不能把无物理单位的示意尺寸声明为“24 小时落尘半径”。


### 3.4 页面与 SEO 产品口径变更（待与其他章节统一）

- 首页 `/`：保留地图选点、城市检索、URL 状态、移动端体验及文献条目检索；参考资料只在其**原始文献情境**中呈现。不能把不同当量的效应参考半径按地理比例覆盖在用户选择的真实地点；地图上可以有不带距离刻度、明确为示意的视觉层。
- `/blast-radius/`：建设移动端可读、关闭 JavaScript 仍可访问的原始文献索引、测量定义、来源链接/书目信息和历史事实对照；不自动生成跨当量的可用于真实地点破坏范围评估的精确数值矩阵。没有源记录，不虚填表格。
- `/:city/`：维持 20 城市静态页、地名及行政区域人口背景与知识解读，但城市内容**不宣称已计算核爆损害或“对应城市的真实破坏圈”**。原 `what would happen if a nuke hit <city>` 关键词不再直接作为不符合正文内容的预测承诺；SEO 标题与 H1 须在下一轮第 6 节统一改成能被实际内容支持的表述。
- `/fallout-map/`：严格沿用本节 3.3，只有非预测性风向示意与历史案例时间轴；不生成地点级沉降足迹。
- 世界人口数据沿用第 4 节：行政区域背景人口，不与核效应圈做空间叠算，不标为人员伤亡或“受影响人口”。

### 3.5 验收更新、来源核对与限制披露

**删除原 `computeImpact(...)` 作为本阶段验收项**。替代核验内容：所有实际公开展示的来源数字都有可追溯的章节、图/表、纸本页码与原始读数记录；不具有出处的记录不展示；随机抽 5 条人工核对原文必须一致；绝不插值、拟合、外推或用其他网页的近似值替代。

技术验收继续保留：关键内容关闭 JS 可读、交互目标 ≤300 ms（明确测试设备与 P95 口径）、URL 可分享、构建期 1200×630 PNG、JSON-LD、内部链接与 canonical。OG 卡片不暗示已预测任何真实地点的核打击范围；任意查询参数不能由纯 SSG 实时生成独立 OG 图片。

**`/methodology/` 必须说明**：1977 年参考资料的年份和出版性质、人工转录与读图的区别、原资料条件限制、纸本页码与 PDF 页序的区别、非预测性图形的性质、历史数据不代表今日城市条件、行政区域人口与实时在场人口的区别，以及哪些结果没有计算（地点级破坏圈、落尘覆盖、剂量、伤亡与受影响人口）。

**未解决冲突必须显式标注为 `BLOCKED`**：原需求希望地图对任意真实城市显示按当量缩放的准确效应圈，而这里的可交付范围不支持该能力；既不能把“文献转录”当作规避这一风险的依据，也不能将不符合实际产品的关键词和验收表悄悄标为 PASS。

## 4. 人口与地名数据：来源、许可和预处理

### WorldPop

**数据版本锁定（仅用于不与攻击后果关联的行政城市人口背景）**：WorldPop **Global2 / R2025A / v1 / 2025 年**；数据集为 WGS84、30 角秒（赤道附近约 1 km，**不是全球恒定 1 km 网格**）、`people per pixel` 人口计数（不是 `people/km²` 人口密度）。Global2 2025 全球镶嵌 GeoTIFF 数据源：

- 文件 URL：`https://data.worldpop.org/GIS/Population/Global_2015_2030/R2025A/2025/0_Mosaicked/v1/1km/constrained/global_pop_2025_CN_1km_R2025A_v1.tif`
- 元数据与原始下载页：https://hub.worldpop.org/geodata/summary?id=80031 ；全球 1 km 系列：https://hub.worldpop.org/project/categories?id=3 ；程序化文件索引：https://api.worldpop.org/v3/documentation
- 全球镶嵌数据 DOI：`10.5258/SOTON/WP00845`（正式构建时仍逐项核验数据文件与版本的 DOI 对应关系）。许可信息须以实际文件元数据为准：WorldPop 官网列出 CC BY 4.0，也提示部分引自 OSM/微软足迹或道路数据的派生数据可能涉及 ODbL 归属或衍生数据要求；不能用统一的“所有文件均 CC BY”代替逐文件验证。
- **质量标签**：WorldPop 官方将 R2025A 标成 **alpha 版本**，数值是建模得到的居住人口估计，不能称为 2025 实时人口、街区现场人数或人员伤亡数。

**预处理规则（城市行政区统计，不计算核爆影响区）**：

1. 下载只用于 20 城市所在区域的必要文件或全球源的对应裁剪，保存 `source_url`、DOI、`release`、版本、下载日期、哈希与许可；原始 GeoTIFF 不发布到浏览器。
2. 在 `scripts/data/` 的构建期 Python 任务中以 `rasterio/GDAL` 读取人口栅格，以 `pyproj/shapely` 读取并规范化**有明确来源的城市行政边界**；只在规范的等面积 CRS 中算面积比例，避免直接拿经纬度度数当面积。
3. 选用**按面积覆盖比例加权的栅格人口求和** `Σᵢ pᵢ × fᵢ(G)` 作为城市背景人口口径；完全落入的格子 `fᵢ=1`，部分相交时 `0<fᵢ<1`，`NoData` 不当成 0，统计有效栅格覆盖率。边界内“按中心点取一个栅格值”不能当城市人口；“只统计中心点落在边界内的整格求和”可做质量对照，但边界有离散化偏差。
4. 对每城生成静态 JSON，包括 `population_estimate`、`population_year`、`boundary_source`、`boundary_type`、`grid_release`、`grid_resolution`、`method`、`valid_cell_fraction`、`source_url`；按行政市/都市区分别定义而不是混用。
5. 抽查边界跨海、跨河、岛屿及稀疏人口区，记录面积加权与中心点整格纳入的差异，并用独立城市统计口径辅助发现错误（不要求两个来源数字相同）。

**语义判定**：人口栅格的**区域求和**才是与“某区域人口”匹配的统计操作；“取点击中心像元的一个数字”不等于“整片区域人口”。然而所谓 **`affectedPopulation`** 需要先定义有独立科学验证的影响边界、阈值、时段、人口暴露、建筑/避险与其他条件，不能拿“行政区人口”或“某个栅格人数”冒充，也不能在本期把核爆效应圈与人口数据联算。

**“中心点 vs 区域求和差几倍”的回答**：如果“取中心点”是只取一个 1 km 像元，而“圆内求和”是许多像元之和，**没有普适倍数，0、几十、数千甚至更大的比值在抽象几何与分布上都可能出现**；分母为 0 时倍数本身没有定义。该数字强烈依赖区域大小、位置、栅格分辨率与人口密度，无法在不指定场景和运行数据的情况下报一个可信“数量级”。由于本期不做真实核爆地点的影响人口空间叠算，验收中不承诺该倍数。

**资源预算限制**：不可能在纯 SSG 中同时承诺全球任意点、任意范围、1 km 精度、首包极小、绝对零业务数据下载与首点 300 ms。本期构建期只导出固定 20 城市及其边界口径一致的背景数据；浏览器无 WorldPop 在线 API 请求。

### GeoNames

下载官方每日离线导出，基于城市别名、ASCII 名、国家/地区/坐标去重；保留 20 城市的官方或公认英语名称及国家消歧。GeoNames 数据为 **CC BY**，支持商业使用；只使用下载数据，不使用其受配额限制的在线搜索接口。城市介绍不能由地名数据库“自动编造”，需单独事实核查、英文编辑。

## 6. SEO 内容契约（只做阶段一）

每条已批准页面独立配置 `title`、`h1`、`description`、`canonical`、`ogTitle`、`ogImage`、`internalLinks`、`schema`。关键字映射保留：

| 路由 | 主关键词 | 处理 |
|---|---|---|
| `/` | `nuke simulator` | Title 与 H1 都出现词组且不重复为同一句；正文避免虚构计算承诺 |
| `/blast-radius/` | `nuclear bomb blast radius` | 解释已公开测量及研究中的半径定义，首屏有可读表格 |
| `/fallout-map/` | `fallout map` | 描述示意风向和历史公开观测，不宣传实时辐射预测 |
| `/nuclear-bomb-map/` | `nuclear bomb map` | 独立导航入口、城市与研究资料索引 |
| 20 城市页 | `what would happen if a nuke hit <city>` | 关键词需与实际受支持内容匹配，不能用人口背景伪装成地点预测 |
| `/nuclear-winter/` | `nuclear winter` | ≥3000 英文词、可核验图表与来源 |

- Title / H1 各自原创且包含主词；description 逐页编写；`og:title === document.title` 在构建期断言。
- `canonical` 必须是 `https://apocalab.com/...`，不带预览域名，也不将任意 URL 参数单独当成可收录页面。
- `sitemap.xml` 来自 Astro SSG 构建的全部准入路由，`robots.txt` 指向正式 sitemap；阶段二批准后才自动新增第二阶段路由。
- 首页/可见 FAQ 区加准确匹配页面可见问答的 `FAQPage`；城市页加 `BreadcrumbList`。注意：Google 对普通商业网站的 FAQ 富摘要展示已经受限，**写上 Schema 不保证搜索结果出现 FAQ 富摘要**。
- 关闭 JavaScript 仍能看见主标题、核心文章、表格、地名信息、至少三条有效站内链接；城市页必须链接首页与 `/blast-radius/`。

- 禁止出现历史 demo 的营销/占位语句及整段旧文案。上线前通过字符串扫描、链接扫描与 HTML 断言检查。
- 不承诺通过 SEO 技术本身取得搜索排名；先保证可索引、准确、速度与内链。

## 7. 状态、动画、响应式与验收测试

### URL 和状态

- 约定 `?lat=&lng=&kt=&z=` 是兼容旧分享链接的解析格式。`kt` 可以作为**选择与显示的历史情境标记**，不得成为前端计算地点级武器后果的输入。
- 额外使用 `mode`、`wind`、`t` 表示说明视图、示意方向和时间帧；参数值有限集合校验、经纬度边界检查、纠错和 URL 去噪。
- 浏览器 Back/Forward 能还原状态；不刷新可切选项，所有浏览器交互都有可触摸的替代按钮。
- 动画状态机 `idle → selected → playing → finished`，播放时锚点不可变，结束保留静帧；重新选点才复位。尊重 `prefers-reduced-motion`。

### 视觉与数据分离

“有来源的数字”放在 HTML 结果表或数据卡；动画独立透明层，使用不同线型/图例，任何装饰图形不得借用数据量纲。没有被验证为地点级物理范围的圆形不得描成“真实计算范围”。页面不以大段免责声明占据首屏；只在图例、方法页以及需要解释数据类型的位置作必要说明。

### 性能预算和测量

| 指标 | 目标 | 如何验收及限制 |
|---|---|---|
| 首屏 2 s | 静态主体、地图区域、默认数据均可见 | 以约定网络与手机设备做 WebPageTest / Lighthouse 实测；瓦片完整加载不保证 2 s |
| 交互 300 ms | 输入到**本地展示层**状态更新 ≤300 ms | 预加载后取 P95；排除首次全球数据下载；不能把异步未知数假报成功 |

| 多层风切变、锋面变化与强降水使简化落尘示意不代表真实地点轨迹 | `/fallout-map/` 的 0/6/12/24 h 与风向选择 | 图例标 `Illustrative wind direction — not a deposition forecast`，不发布有地理刻度的沉积量/剂量等值面 |
| WorldPop Global2 R2025A v1 属 alpha 版且表征的是估计居住人口 | 20 城市页的 `Population context` | 同屏标 `WorldPop 2025, R2025A v1 (alpha); modeled residential population`，链接数据源与版本 |
| WorldPop 每像素人数 vs 人口密度、经纬度栅格“约 1 km”不等于恒定 1 km² | 20 城市人口 JSON、城市页人口卡 | 构建期断言单位、覆盖率与面积计算 CRS，禁止直接把像元总人数再乘一次面积 |

| 海岸、岛屿或缺值栅格交界使裁剪覆盖比例不稳定 | 旧金山、迈阿密、悉尼等城市人口背景 | 对边界栅格面积加权、显示有效覆盖率和源数据 NoData 标志；不把 NoData 当零 |
| 公开地图与备用均无 SLA；主源样式可用不等于瓦片/字体/图标全部可用 | 首页、城市页和所有地图页面 | 单一配置入口、独立服务切换，全部失败保留 `#0B0E13` 深底、示意层和 `Map tiles unavailable`；真实测试前不标通过 |
| VersaTiles 预置样式版本可能变化，TileJSON 相对路径或 attribution 丢失可导致白图或失署名 | 地图备源 `gray-dark` 和地图右下角 attribution | 版本固定、构建期校验 style/TileJSON/glyph/sprite，必要时自托管 style；来源切换时同步显示正确署名 |
| 纯 SSG 无法为任意查询坐标即时生成不同的 1200×630 OG 图片 | 首页可分享 URL、`/fallout-map/` 分享卡 | 固定城市/案例预渲染 PNG；任意坐标的分享链接复用所属路由默认 PNG，方法页明确此为静态预览，不造假实时数值 |
| “城市人口背景”与“受核事件影响人口”混为同一数字 | 首页 `affectedPopulation` 需求、城市页 OG 图片、订阅说明 | 保留 `Population context` 的独立定义；未验证的地点预测不使用 `affected` / `casualties` 标签，原字段验收保持 `BLOCKED` |

**第 4 个月开始收取 $10/月后最容易被质疑的数字（按风险优先级）**：首先是**“受影响人口”**（用户会误读为实时在场人数/伤亡预测，且对边界与时段极敏感）；其次是**落尘抵达时间、浓度或轨迹**（风场与降水可令预测偏离真实位置）；然后是**热辐射阈值圈**（判据/天气/遮挡不同会显著改变含义）；最后是**1 psi/5 psi 等压半径和火球范围**（自由场理想化假设、爆高、地形与高当量外推）。目前这些地点级数字**没有可用于订阅交付的可信、经过验证的误差量级**；不能因收费而填出一个看似专业的百分比。

`/methodology/` 应对**每个实际发布的数字**给出英文 `Definition / Source / Dataset version / Geography / Measurement conditions / Method / Known biases / Validation status / Last reviewed`，并把“输入范围、缺失变量、适用场景、没有计算什么”集中说明：例如 `City population is a modeled residential estimate, not the number of people present or harmed by an event.`；对未验证的地点级模型明确 `No validated location-specific forecast is provided.`。如有多个真实研究结果且计算条件不同，展示研究之间的差异及适用场景，**不要把差异伪装成模型置信区间**。订阅文案和付费对照表不能把研究对比、抽象示意和真实危险评估混写。

- OpenFreeMap 官网：<https://openfreemap.org/> — 公共服务免费、不限公开浏览请求、无 API Key、商业用途允许及展示署名。
- OpenFreeMap 样式仓库：<https://github.com/hyperknot/openfreemap-styles> — Dark 与 Fiord 的样式端点、维护状态。
- OpenFreeMap Quick Start：<https://openfreemap.org/quick_start/> — MapLibre 集成与公开样式。
- VersaTiles 公共服务条款：<https://docs.versatiles.org/guides/use_tiles_versatiles_org> — 无保障、限速、缓存、样式变更和署名。
- WorldPop Global2 人口资源：<https://hub.worldpop.org/project/categories?id=3> — 1 km 全球 2015–2030 年系列及选择指引。
- WorldPop API 数据与版本说明：<https://api.worldpop.org/v3/documentation> — 数据 DOI、国家/全球文件、授权元数据。
- GeoNames 数据许可：<https://www.geonames.org/export/> — 离线数据 CC BY、商业使用、归属要求。
- Astro 路由与预渲染：<https://docs.astro.build/en/reference/routing-reference/>。
- Google Search JavaScript SEO：<https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics> — 预渲染内容和 canonical 建议。
- Google FAQ 富摘要政策：<https://developers.google.com/search/blog/2023/08/howto-faq-changes> — FAQ 富摘要大多限于权威政府/健康类站点。
